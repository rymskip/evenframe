# refactor(tooling): build every test under one feature resolution

- **Date:** 2026-11-22 23:10
- **Commit:** this commit
- **Area:** Tooling, verify, contributor guide

## Problem

`verify` compiled the dependency tree several times: after a lockfile update, `serde_json` built
six times in one run and 186 of 267 crates more than once. `pixi run test` did the same.

## Cause

The core, snapshot, CLI and derive tests were separate `cargo test` invocations, each selecting
its own package and features (`-p evenframe_core --features full`, `--features typesync-all`,
`-p evenframe`, `-p evenframe_derive`). Cargo unifies a dependency's features only within one
invocation, so `serde`, `chrono`, `libc`, `memchr`, `regex-automata`, `syn` and others resolved
differently in each step, and a crate's build hash covers its dependencies', which rebuilt
everything above them.

## Introduced

The per-package test steps predate this branch's history.

## Fix

`verify` runs every test as one `cargo test --workspace --all-features`, the resolution clippy
checks. `pixi run test` runs the same, and `--snapshot` narrows it to the snapshot target instead
of choosing other features; the `--features` options are gone. The `derive_check` step keeps its
three feature combinations, which is what it tests. `AGENTS.md` is tracked, with its test,
logging, configuration and commit guidance corrected to match the code.

## Verified

`pixi run verify` passed all 9 steps (run `20261123T035543Z`, 1704 tests). In that run
`serde_json` compiled twice, once checked for clippy and once built for the tests, and the
workspace's tests built in one pass; testground, a separate workspace, builds its own graph.
