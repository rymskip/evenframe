# refactor(log): turn debug logging on with EVENFRAME_LOG_DIR, not a feature

- **Date:** 2026-11-22 23:05
- **Commit:** this commit
- **Area:** Logging, features, docs

## Problem

`evenframe_log!` wrote its debug files only in a build with the `dev-mode` feature, so seeing what
schemasync generated meant rebuilding evenframe. The feature also split test builds: a run with
`--all-features` turned it on, wrote log files during the tests, and compiled out the test that
the default build evaluates nothing.

## Cause

A debugging switch was modelled as a compile-time feature, with the output location in a second
variable, `ABSOLUTE_PATH_TO_EVENFRAME`, falling back to the system temp directory.

## Introduced

The `dev-mode` feature and `ABSOLUTE_PATH_TO_EVENFRAME` predate this branch's history.

## Fix

`EVENFRAME_LOG_DIR` names the directory `evenframe_log!` writes to; unset, nothing is written and
the macro's arguments are never evaluated. The `dev-mode` feature and `ABSOLUTE_PATH_TO_EVENFRAME`
are gone, mockmake's failed-upsert entry logs through the macro like the rest, and the CLI and
troubleshooting docs describe the variable. The ignore entries for `evenframe/logs` and for
schema dumps under `evenframe/` went with them: those files only ever landed inside the log
directory.

## Verified

`pixi run verify` passed all steps on the finished branch (run `20261123T035543Z`), including
the two new tests: a log call with no directory evaluates nothing, and entries are written,
appended and truncated inside a directory that did not exist yet.
